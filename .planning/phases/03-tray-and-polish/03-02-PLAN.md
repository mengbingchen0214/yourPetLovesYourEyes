  <files>src-tauri/src/dialogs.rs</files>
  <action>
    Create `src-tauri/src/dialogs.rs` with:

    1. `pick_image(title: &str) -> Option<String>` — uses `tauri-plugin-dialog`'s `FileDialogBuilder`:
       ```rust
       use tauri_plugin_dialog::DialogExt;

       let file = app.dialog()
           .file()
           .set_title(title)
           .add_filter("Images", &["png", "jpg", "jpeg", "gif", "webp"])
           .blocking_pick_file();
       ```
       Returns the selected file path as `Option<String>`.

    2. `copy_image_to_config(src: &str, config_key: &str, app: &AppHandle) -> Option<String>`:

       - Returns the path for the frontend to use

    3. Register as Tauri commands: `pick_sleep_image`, `pick_rest_image`, `pick_tray_icon`, `pick_app_icon`

    4. On the frontend, replace `window.eyePet.pickSleepImage()` → `invoke('pick_sleep_image')` etc.

    What to avoid:
    - Don't use `blocking_pick_file()` on the main thread — it will freeze the UI. Use `async` command + `pick_file()` (non-blocking) instead, or spawn a thread for the blocking call.
    - Don't forget to update the config file after copying the image
    - Don't hardcode the destination directory — use `app.path().app_data_dir()`
  </action>

<task type="auto">
  <name>Task 2: Port text input dialog (greeting text)</name>
  <files>src-tauri/src/dialogs.rs, input-dialog.html</files>
  <action>
    The text input dialog is trickier in Tauri because there's no built-in "input dialog" like Electron's `BrowserWindow` modal.

    Approach: Create a new Tauri window for the input dialog:

    1. `show_text_input_dialog(app: &AppHandle, current_value: &str) -> Option<String>`:
       - Create a new `WebviewWindow` with:
         - url: "input-dialog.html"
         - title: "修改问候语"
         - width: 340, height: 130
         - resizable: false
         - minimizable: false
         - maximizable: false
       - Use `app.emit("text-input-init", current_value)` to send the current value
       - Listen for `text-input-result` and `text-input-cancel` events from the dialog window
       - Return the result

    2. Update `input-dialog.html` to use Tauri's event system instead of Electron's IPC:
       - Replace `window.dialog.onInit()` → `window.__TAURI__.event.listen('text-input-init', ...)`
       - Replace `window.dialog.submit()` → `window.__TAURI__.core.app.emit('text-input-result', value)`
       - Replace `window.dialog.cancel()` → `window.__TAURI__.core.app.emit('text-input-cancel')`

    3. On submit, update config and emit `config-change` event to the main window.

    What to avoid:
    - Don't use a blocking approach — the dialog should be async
    - Don't forget to close the dialog window after submit/cancel
    - Don't use Electron's `ipcRenderer` — use Tauri's event system
  </action>
  <verify>Clicking "修改问候语" opens a dialog. User can type and submit. Greeting text updates in config and on the greeting screen.</verify>
  <done>Text input dialog works. Greeting text updates correctly.</done>

<task type="auto">
  <name>Task 4: Port auto-updater</name>
  <files>src-tauri/src/main.rs, src-tauri/tauri.conf.json, src-tauri/Cargo.toml</files>
  <action>
    1. `tauri-plugin-updater` is already in Cargo.toml (added in Phase 1).

    2. In `tauri.conf.json`, configure the updater:
       ```json
       "updater": {
         "active": true,
         "endpoints": ["https://api.github.com/repos/mengbingchen0214/yourPetLovesYourEyes/releases/latest"],
         "dialog": true,
         "pubkey": "YOUR_ED25519_PUBLIC_KEY"
       }
       ```

    3. In `main.rs`, register the updater plugin:
       ```rust
       .plugin(tauri_plugin_updater::Builder::new().build())?
       ```

    4. On app startup (in `setup()`), check for updates:
       ```rust
       let app_handle = app.handle().clone();
       tauri::async_runtime::spawn(async move {
           match app_handle.updater().check().await {
               Ok(Some(update)) => {
                   // Update available — the plugin handles the dialog
               }
               Ok(None) => { /* No update */ }
               Err(e) => { /* Log error */ }
           }
       });
       ```

    5. Generate an Ed25519 key pair for signing updates:
       ```bash
       cargo tauri signer generate
       ```
       Store the private key securely (GitHub Secrets for CI). Put the public key in `tauri.conf.json`.

    What to avoid:
    - Don't skip signing — unsigned updates will be rejected
    - Don't hardcode the private key in the repo — use environment variables
    - Don't check for updates synchronously — it blocks the UI. Use `spawn`.
    - Don't forget to add `"updater"` to the capabilities file
  </action>
  <verify>`cargo tauri build` produces a signed bundle. Updater checks the GitHub releases endpoint. Update dialog appears when a new version is available.</verify>
  <done>Auto-updater configured. Checks GitHub releases. Signed updates work.</done>
