<task type="auto">
  <name>Task 1: Create the state machine module in Rust</name>
  <files>src-tauri/src/state_machine.rs</files>
  <action>
    Create `src-tauri/src/state_machine.rs` with:

    1. State enum:
       ```rust
       #[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
       pub enum PetState {
           Greeting,
           Sleeping,
           Resting,
           Paused,
       }
       ```

    2. AppState struct (stored in Tauri's managed state):
       ```rust
       pub struct AppState {
           pub pet_state: Mutex<PetState>,
           pub cycle_count: Mutex<u32>,
           pub overlay_enabled: Mutex<bool>,
           pub is_paused: Mutex<bool>,
           pub sleep_end_at: Mutex<Option<Instant>>,
           pub rest_end_at: Mutex<Option<Instant>>,
           pub paused_from_state: Mutex<Option<PetState>>,
           pub paused_remaining_ms: Mutex<u64>,
           pub config: Mutex<Config>,
       }
       ```

    3. State transition functions (all take `State<AppState>` + `AppHandle` for event emission):
       - `start_greeting()` — resets to greeting state, hides overlay
       - `start_sleeping()` — 20-min timer, emits `state-change` event, repositions pet randomly
       - `start_resting()` — 20-sec timer, shows overlay, centers pet, increments cycle_count
       - `pause_cycle()` — captures remaining time, transitions to Paused
       - `resume_cycle()` — restores remaining time, transitions back to paused_from_state

    4. Use `tokio::time::sleep()` for async timers instead of JS `setTimeout`. Spawn them as tokio tasks so they don't block.

    5. After each state transition, emit a Tauri event:
       ```rust
       app_handle.emit("state-change", json!({"state": "sleeping", "cycleCount": 0}))?;
       ```

    Constants: SLEEP_DURATION = 20 * 60 * 1000 ms, REST_DURATION = 20 * 1000 ms.

    What to avoid:
    - Don't use `std::thread::sleep()` — it blocks the main thread. Use `tokio::time::sleep()`.
    - Don't use `setTimeout`/`setInterval` — those are JS. In Rust, use tokio timers.
    - Don't forget to cancel previous timers when state changes. Store `JoinHandle<>` for active timers and abort them on transition.
    - Don't use `unwrap()` on Mutex locks — handle poisoned locks gracefully.
  </action>
  <verify>`cargo build` succeeds. State machine compiles. Unit tests for state transitions pass (e.g., Sleeping → pause → resume preserves remaining time).</verify>
  <done>State machine module compiles. All 5 states and transitions implemented. Timers are async (tokio).</done>
</task>
