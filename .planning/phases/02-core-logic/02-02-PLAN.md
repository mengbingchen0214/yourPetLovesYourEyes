<task type="auto">
  <name>Task 1: Port overlay manager to Rust</name>
  <files>src-tauri/src/overlay.rs</files>
  <action>
    Create `src-tauri/src/overlay.rs` with:

    1. `OverlayManager` struct holding a `Vec<WebviewWindow>` for overlay windows (one per monitor).

    2. `create_overlays(app: &AppHandle) -> Vec<WebviewWindow>`:
       - Iterate `app.all_monitors()` to get all displays
       - For each monitor, create a `WebviewWindow` with:
         - Same size as monitor bounds
         - Position at monitor origin (x, y)
         - decorations: false
         - transparent: true
         - always_on_top: true
         - skip_taskbar: true
         - focusable: false
         - resizable: false
       - Load `overlay.html` in each window
       - Set `ignore_mouse_events` on each window (click-through)

    3. `show_overlays(overlays: &[WebviewWindow])` — calls `show()` on each

    4. `hide_overlays(overlays: &[WebviewWindow])` — calls `hide()` on each

    5. `destroy_overlays(overlays: &mut Vec<WebviewWindow>)` — calls `close()` on each, clears vec

    6. Store `OverlayManager` in the `AppState` struct (from Phase 2, Plan 1).

    7. Call `create_overlays()` during app setup (in `main.rs`). Call `show_overlays()` when entering Resting state, `hide_overlays()` when leaving.

    What to avoid:
    - Don't create overlay windows lazily — create them all at startup and reuse
    - Don't forget `ignore_mouse_events` — the overlay must be click-through
    - Don't use `set_visible_on_all_workspaces` — Tauri handles this differently per platform. On macOS, use `window.set_visible_on_all_workspaces(true)` if available, or accept the default behavior.
    - Don't load overlay.html via `load_file()` — use `WebviewWindowBuilder::new().url("overlay.html")` so it's served from the frontend dist.
  </action>
  <verify>`cargo tauri dev` launches. When entering rest state, gray overlay appears on all monitors. Overlay is click-through. Leaving rest state hides overlay.</verify>
  <done>Overlay windows create on all monitors. Show/hide works with state transitions. Click-through works.</done>
</task>

<task type="auto">
  <name>Task 2: Port drag-to-move system</name>
  <files>src-tauri/src/window_manager.rs, index.html</files>
  <action>
    The drag system needs to work differently in Tauri because there's no synchronous IPC like Electron's `ipcRenderer.send()`.

    Approach: Use Tauri's `start_dragging()` API (Tauri 2.x built-in window drag):

    1. In the pet window setup, enable the `"tauri"` allowlist in `capabilities/default.json`:
       ```json
       "permissions": ["core:window:allow-start-dragging", "core:window:allow-set-position", ...]
       ```

    2. In `index.html`, replace the manual drag implementation with:
       ```javascript
       petContainer.addEventListener('mousedown', (e) => {
         if (e.button === 0) {
           window.__TAURI__.core.window.getCurrentWindow().startDragging();
         }
       });
       ```

    3. If `start_dragging()` doesn't work well with transparent windows (known issue on some platforms), fall back to manual tracking:
       - `mousedown`: store offset, call `invoke('start_drag', {x: e.screenX, y: e.screenY})`
       - `mousemove`: call `invoke('drag', {x: e.screenX, y: e.screenY})`
       - `mouseup`: call `invoke('end_drag')`
       - In Rust: `start_drag` stores offset, `drag` calls `window.set_position(LogicalPosition::new(x - offset_x, y - offset_y))`, `end_drag` saves position to config

    4. On `end_drag`, save the window position to config (persist across restarts).

    What to avoid:
    - Don't use Electron's `ipcRenderer.sendSync()` — Tauri has no sync IPC
    - Don't forget to save position on drag end — users expect the pet to stay where they put it
    - Don't block the UI thread during drag — use Tauri's native drag if possible
  </action>
  <verify>User can drag the pet window to any position on screen. Position persists after drag ends. Position restores on app restart.</verify>
  <done>Drag-to-move works. Position saves to config. Position restores on restart.</done>
</task>

       ```rust

           if let WindowEvent::CloseRequested { api, .. } = event {

               window.hide().unwrap();
       ```
