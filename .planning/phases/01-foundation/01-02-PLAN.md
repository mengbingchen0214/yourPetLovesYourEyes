<task type="auto">
  <name>Task 1: Port config load/save to Rust</name>
  <files>src-tauri/src/config.rs</files>
  <action>
    Create `src-tauri/src/config.rs` with:

    1. A `Config` struct with serde::Serialize/Deserialize:
       ```rust
       #[derive(Debug, Clone, Serialize, Deserialize, Default)]
       pub struct Config {
           pub sleep_image: Option<String>,
           pub rest_image: Option<String>,
           pub tray_icon: Option<String>,
           pub app_icon: Option<String>,
           pub greeting_text: Option<String>,
           pub saved_position: Option<Position>,
       }

       #[derive(Debug, Clone, Serialize, Deserialize)]
       pub struct Position {
           pub x: i32,
           pub y: i32,
       }
       ```

    2. `load_config(app: &AppHandle) -> Config` — reads from `app.path().app_data_dir()/config.json`. Returns default Config if file doesn't exist. Uses `std::fs::read_to_string` + `serde_json::from_str`.

    3. `save_config(app: &AppHandle, config: &Config)` — writes to the same path. Creates parent dirs if needed with `std::fs::create_dir_all`.

    4. Register `load_config` and `save_config` as Tauri commands using `tauri::generate_handler!`.

    What to avoid:
    - Don't use `app.getPath('userData')` — that's Electron. In Tauri, use `app.path().app_data_dir()`.
    - Don't panic on missing config file — return default Config gracefully.
    - Don't use `unwrap()` in production code — use `match` or `if let` for error handling.
  </action>
  <verify>`cargo build` succeeds. Commands are registered and callable from frontend via `invoke('load_config')`.</verify>
  <done>Config can be loaded and saved from Rust. Config file persists in app data directory.</done>
</task>

<task type="auto">
  <name>Task 2: Port pet window creation and management</name>
  <files>src-tauri/src/window_manager.rs, src-tauri/src/main.rs</files>
  <action>
    Create `src-tauri/src/window_manager.rs` with:

    1. `create_pet_window(app: &AppHandle) -> Result<WebviewWindow>` — creates the main pet window with:
       - 200x260 size
       - decorations: false
       - transparent: true
       - always_on_top: true
       - resizable: false
       - skip_taskbar: true
       - Random initial position within screen bounds (use `app.primary_monitor()` to get screen size)

    2. `set_pet_position(window: &WebviewWindow, x: i32, y: i32)` — moves the window

    3. `center_pet_window(window: &WebviewWindow)` — centers on primary display

    4. `show_pet(window: &WebviewWindow)` / `hide_pet(window: &WebviewWindow)` — visibility toggles

    5. Register these as Tauri commands.

    In `main.rs`:
    - Set up the window in `setup()` hook using `tauri::Builder::setup()`
    - Load `index.html` as the main page (Tauri serves from frontendDist automatically)
    - Store the window handle in Tauri's state for later access

    What to avoid:
    - Don't create the window in `main()` directly — use the `setup()` hook so you have access to `AppHandle`
    - Don't hardcode screen dimensions — query the monitor at runtime
    - Don't use `BrowserWindow` — that's Electron. In Tauri it's `WebviewWindow`.
  </action>
  <verify>`cargo tauri dev` launches. Pet window appears at a random position. Window is borderless, transparent, always-on-top. `invoke('center_pet')` centers it.</verify>
  <done>Pet window creates correctly. Position commands work. Window properties match Electron behavior.</done>
</task>

<task type="auto">
  <name>Task 3: Wire up frontend IPC to Tauri commands</name>
  <files>index.html</files>
  <action>
    Replace the Electron IPC calls in `index.html` with Tauri command invocations:

    1. Replace `window.eyePet.getConfig()` → `invoke('load_config')`
    2. Replace `window.eyePet.getState()` → `invoke('get_state')` (we'll implement this in Phase 2)
    3. Replace `window.eyePet.startCycle()` → `invoke('start_cycle')` (Phase 2)
    4. Replace `window.eyePet.onStateChange(callback)` → Tauri events: `listen('state-change', callback)` from `@tauri-apps/api/event`
    5. Replace drag IPC (`start-drag`, `drag`, `end-drag`) → `invoke('start_drag', {x, y})`, etc.
    6. Replace `window.eyePet.quitApp()` → `invoke('quit_app')`

    Add at the top of the `<script>` section:
    ```javascript
    import { invoke } from '@tauri-apps/api/core';
    import { listen } from '@tauri-apps/api/event';
    ```

    For the drag system, keep the same mousedown/mousemove/mouseup listeners but call `invoke('drag', {x, y})` instead of `ipcRenderer.send('drag', {x, y})`.

    What to avoid:
    - Don't import `@tauri-apps/api` via CDN — it should be bundled. But since we have no bundler, use the CDN approach: `<script src="https://unpkg.com/@tauri-apps/api@2/dist/tauri.js"></script>` or copy the ES module locally.
    - Actually, the simplest approach: use `window.__TAURI__.invoke()` and `window.__TAURI__.event.listen()` which are available globally when running in Tauri. No imports needed.
    - Don't remove the `window.eyePet` fallback yet — keep it for development testing outside Tauri.
  </action>
  <verify>`cargo tauri dev` launches. Frontend loads. Config loads from Rust. Drag calls `invoke('drag')`. No JS console errors.</verify>
